# 观星指数页：城市搜索前缀树（trie）改造计划

- 分支：`feat-260912-city-search-trie`
- 日期：2026-09-12
- 范围：`web/` 前端（后端零改动）
- 范围决策：**只做中国城市、只做中文名前缀匹配**（按用户要求不引入拼音/首字母，无第三方运行时依赖）

---

## 1. 背景：为什么现在的搜索「非常难受」

现状实现：`<input list="cityList">`（原生 `<datalist>`）+ 唯一搜索源 Open-Meteo Geocoding 网络接口 + 「查阅」按钮做**精确等值**匹配。

三个根因（均经实测）：

### 根因 1：`<datalist>` 是浏览器原生控件，我们控制不了它
- 候选列表由浏览器绘制：无前缀高亮、无「第几条」提示、条数固定
- 中文输入法**组合态（composition）期间**候选常常不刷新，打完字还得再敲一下方向键
- 只能靠 `@change`（失焦/回车）拿到值，用户直接点「查阅」时输入值往往还没同步

### 根因 2：唯一搜索源是网络接口，且对中文前缀很弱

```
输入        改造前（Open-Meteo）                 期望
成      →   0 条                               成都市…
成都    →   4 条：成都/四川、成都/江西…         成都市/四川（首选）
chengdu →   6 条（含 Chengdun/湖北 之类噪声）    —（按需求不再支持拼音）
冷湖    →   1 条：冷湖/青海 ✓                   ✓
赛什腾  →   0 条                                （无权威数据源，暂不支持）
```

Open-Meteo 要**整词**才有结果、单字直接 0 条；且每次输入都要防抖 + 网络往返。

### 根因 3：「查阅」语义与用户预期不符
```ts
const hit = store.searchResults.find((r) => r.name === q)   // 精确等值
if (hit) { ... }
toast.show('未找到该城市，请先查询再查阅', 'info')            // ← 用户看到的提示
```
用户输入「成都」后直接点「查阅」，只要没从下拉里点过那一项，就命中不了 → 弹出这句提示。

## 2. 目标 / 非目标

**目标**
1. 输入即出结果（**零网络延迟**）：中文名前缀匹配，省 / 地级市 / 区县三级全覆盖
2. 自绘下拉：前缀高亮、层级标签（省级/地级市/区县 + 省份面包屑）、键盘 ↑↓/Enter/Esc 操作
3. 「查阅」= 取当前高亮项（无高亮取首条命中），彻底消灭「请先查询再查阅」这类提示
4. 数据**离线可用**（断网也能搜中国城市），不依赖外部接口可用性

**非目标**
- 不支持拼音 / 首字母输入（用户明确要求只做中文）
- 不支持海外城市
- 不支持镇级/景区（如赛什腾山）手工造点；仅由在线兜底覆盖一部分（见 §6）
- 不改后端 `/api/index`、不引入后端城市库

## 3. 数据源与产物（已实测）

**DataV.GeoAtlas 行政区划**：`https://geo.datav.aliyun.com/areas_v3/bound/all.json`

- 单次请求 **340 KB**，返回 3238 条（国级 1 + 34 省 + 363 地级市 + 2840 区县），过滤掉国级后 **3237 条**
- 每条自带：`name`（含「市/县/区」后缀）、`adcode`、`lng`、`lat`、`level`、`parent`（父级 adcode）
- 一次抓取、离线生成、运行时零网络

**生成产物**：`web/public/data/cn-cities.json`（**进仓库**，由 `web/scripts/gen-cities.mjs` 生成）

```json
{ "v": 1, "generated": "2026-09-12", "src": "DataV.GeoAtlas areas_v3/bound/all.json",
  "items": [ ["成都市", 104.0657, 30.6595, 1, 21], ... ] }
```

元组：`[名称, 经度, 纬度, 层级, 父级下标]`

| 项 | 实测值 |
|---|---|
| 条目数 | 3237（省级 34 / 地级市 363 / 区县 2840） |
| 体积 | **100.2 KB**（原始 JSON），**45.3 KB**（gzip） |
| 每条约 | 31 B |
| 坐标精度 | 4 位小数（≈11 m，足够城市级定位） |
| 建索引耗时 | 约 5 ms（3237 条插入前缀树） |
| 前缀查询耗时 | < 0.05 ms/次（扁平过滤也是这个量级，见 §4） |

**踩过的两个坑（已修，生成脚本内置自检）**
1. **父级下标错位**：原始数组含国级，过滤后仍用原始下标 → 整条父级链指错行（成都市 的父级指向自己）。
   现在用「过滤后数组」重建 adcode→下标映射，并在生成时断言：省级无父级、父级层级必须更高、父级不能是自己。
2. 拼音字段（已随范围决策移除）当时的 `ü` 归一化问题 → 现在无拼音字段，不存在该问题。

**许可提示**：DataV 数据用于非商用/学习类作品；生成脚本保留 `src` 字段注明来源，本文件存档此说明。商用需另行确认授权。

## 4. 索引结构：前缀树（trie）

```ts
interface TrieNode {
  children: Map<string, TrieNode>   // 下一个字符 → 子节点
  hits: number[]                    // 以该节点结尾的条目下标
}
```

- 构建：把 3237 个**中文城市名**逐字插入同一棵树（`for...of` 按 code point 迭代，中文安全）
- 查询：沿树下行到输入末尾，再**深度优先枚举该子树**得到全部候选（等价于 `startsWith` 语义，天然按前缀分组）
- 上限：单次最多收集 400 个候选（防单字查询遍历过大），排序后只取前 8 条

**「值不值得用 trie」的诚实说明**：3237 条上扁平 `filter(startsWith)` 实测 **0.03 ms/次**，性能根本不是瓶颈。用 trie 的真实收益是：
1. 前缀分支天然分组（输「成」→ 成都市 / 成县 / 成安县…），便于按层级/权重排序与高亮
2. 未来加别名键（旧名、简称、观星点别名）只是多 `insert` 一次，不改查询代码
3. 查询不随数据增长线性扫描（虽然当前规模下这点无关紧要）

（只做中文单键后，trie 相对扁平过滤的优势进一步缩水；保留它主要为可扩展性与整洁度。）

## 5. 匹配与排序

**匹配**：输入 trim 后沿树下行；中途无子节点即 0 命中。中文不做大小写/编码变换。

**排序**（依次比较，稳定）：

1. **exact**：输入恰好等于某个城市全名（如输入「成县」）→ 排最前
2. **预设优先**：`PRESET_CITIES`（20 个精选城市）同分时排前 —— 例如「南」优先给 南京市 / 南昌市，「贵」优先给 贵阳市 而非 贵港市
3. **层级**：省(2) > 地级市(1) > 区县(0)
4. **名称长度**：短的优先（更贴近输入的「主干」）
5. 兜底：数据序（adcode 序），保证结果稳定可测

**结果行文案**（面包屑由数据集 `parent` 链推出）：

```
成都市   四川省 · 地级市
锦江区   四川省 · 成都市 · 区县
四川省   省级
```

## 6. 在线兜底（本地 0 命中时）

本地表覆盖不到镇级/景区（例：`冷湖`、`纳木错` 实测 Open-Meteo 有，`赛什腾` 全网无权威数据）。因此保留一条**兜底路径**：

- 触发条件：本地 0 命中 **且** 输入长度 ≥ 2
- 请求：`searchCity(q, signal)` 增加 `countryCode=CN`（实测「冷湖」→ 冷湖/青海 38.74,93.33 ✓）
- 防抖 250ms（`ONLINE_FALLBACK_DELAY_MS`）+ 代次号丢弃过期查询
- 展示：下拉里标注来源「在线」，不与本地结果混排
- **本地有命中时绝不发请求**（这是与改造前最大的差别）

## 7. 交互设计（自绘下拉替代 datalist）

| 行为 | 规则 |
|---|---|
| 输入 | 每次 `input` 事件（含 IME 组合态，直读 `el.value`）立即本地查询，**无防抖** |
| 下拉 | 最多 8 条；`<mark>` 高亮匹配前缀；悬停/键盘移动同步高亮索引 |
| 键盘 | `↑`/`↓` 移动（循环）、`Enter` 确认高亮项（无高亮取首条）、`Esc` 关闭、点击外部关闭 |
| 点击「查阅」 | 取高亮项，否则首条命中；**无输入**才提示「请输入要查询的城市名」 |
| 无命中 | 本地 0 条 → 等在线兜底；在线也 0 条 → 提示「未找到…」 |
| 加载 | 首次聚焦搜索框时 `fetch` 城市数据（见 §8），期间显示「载入城市表…」 |
| 视觉 | 沿用图版风格（米色纸、虚线边、衬线字），与 `star-atlas.css` 一致 |

> 城市栏只保留「输入框 + 查阅 + 自动定位」三个控件；原来的「预设城市…」下拉已删除
> （`PRESET_CITIES` 列表保留，但只作为 §5 的**同分排序权重**内部使用，不再有 UI）。

选中后仍走既有 `store.selectSearchResult()` / `store.load()` 路径（区间选择保持不变）。

## 8. 体积与加载策略

- 数据文件在 `public/data/cn-cities.json`，**不进首屏 bundle**（实测 `dist/assets/*.js` 中搜不到城市名）
- 运行时按 `${import.meta.env.BASE_URL}data/cn-cities.json` 取值 → 支持子路径部署；Vite 原样拷贝到 `dist/data/`
- 首次聚焦搜索框才请求（100 KB / gzip 45 KB，同源静态资源，可长缓存）
- 索引树在数据到达后构建一次（约 5 ms），作为模块级单例缓存；加载失败不缓存，可重试

## 10. 验收标准

1. 输入 `成` 立即出列表，首条为「成都市 · 四川省 · 地级市」，`<mark>` 只高亮「成」
2. 输入 `锦江` 出「锦江区 · 四川省 · 成都市 · 区县」（三级面包屑）
3. 中文输入法打字（组合态）过程中列表跟随更新，无需额外按键
4. 输入 `成都` 直接点「查阅」→ 加载成都指数；**不再出现**「未找到该城市，请先查询再查阅」
5. 输入 `冷湖` 走在线兜底并返回「冷湖 · 在线 · 青海省」
6. 断网状态下中文搜索全部可用（在线兜底静默失败，不影响本地结果）
7. `pnpm test`、`pnpm build`、后端 `pytest -q` 全绿；首屏 bundle 无城市数据

## 11. 风险与边界

- **同名地**：全国区县级重名较多（城关区、新城区…）→ 靠面包屑（父级链）区分，不做合并
- **数据时效**：行政区划会变（撤县设区等），数据为生成日快照；脚本可重跑更新，文件内记录 `generated`
- **不造数据**：镇级/景区坐标**不手工编造**，只由在线兜底覆盖，避免出现无法溯源的坐标
- **仅中文**：拼音/首字母输入不再命中（`cd`、`chengdu` 返回空）——这是需求决定，若日后要恢复，只需在 `gen-cities.mjs` 增加拼音键字段并在 `cityTrie.ts` 的键集合里注册
